# Proof And Gaps

This file is intentionally short. The project no longer treats a large host
script suite as the source of truth. New claims should come from guest OS status
fields, assembly/C code running in vibe-os, tiny C host validators, shell
workflow checks, and disposable cloud boots.

## Current Playable Claim

vibe-os can boot in cloud QEMU and play the original `linuxdoom-1.10` port with
real shareware `DOOM1.WAD` through Codespaces/noVNC.

The meaningful current claims are:

- BIOS boot path reaches the 32-bit kernel and Stage 2 prefers the FAT16
  `KERNEL.ELF` file before the raw-LBA fallback after validating the file's
  FAT16 cluster bounds and end-of-chain marker.
- The kernel owns interrupts, paging, timer ticks, input, framebuffer, storage,
  a heap, syscalls, and user process launch.
- Doom runs as a Ring 3 ELF process, not as a host app.
- Doom reads WAD data through the OS file path and presents frames through the
  OS graphics path.
- The generic ABI probe now exercises the VFS syscalls used by other programs:
  open, read, write, lseek, stat, fstat, listdir, unlink, ftruncate, and close.
- The safe manual play path runs QEMU only on a disposable cloud host.

## Proof Commands

Host-only checks:

```sh
make ALLOW_LOCAL_VM=0 DOOM_WAD= build-only
make ALLOW_LOCAL_VM=0 DOOM_WAD= test
make ALLOW_LOCAL_VM=0 DOOM_WAD= playability-host-check
```

`tools/vibe_status_check.c` is the current compiled host validator for guest
status text. It is intentionally small and should not grow into a replacement
operating system.

Disposable cloud checks:

```sh
gh workflow run os-smoke.yml --ref main -f expected_ref=main
gh workflow run real-wad-smoke.yml --ref main -f expected_ref=main
```

Manual play:

```sh
./tools/play_now_codespaces.sh --repo jadentripp/vibe-os --ref main
```

## Gap Ledger

- `GAP[UEFI_BOOT] status=partial`: prove-mode cloud run `26290689684` on
  `main` first proved the UEFI loader reached the kernel, storage, and WAD
  path, but faulted while execing `ABIPROBE.ELF`. The follow-up prove run
  `26291808070` fixed that address-space bug and reached `path=DOOM.ELF`,
  `abiexec=OK`, `abiprobe=OK`, `doom=OK`, `doomrun=EXIT`, and `panic=NONE`.
  Run `26292559171` kept that path green and added `execcopy=` guest evidence:
  nine ELF segment materializations, nine target-CR3 switches, and nine
  restores, ending in the Doom process page directory.
  The remaining gap is interactive UEFI playability; the noVNC play target is
  still BIOS/IDE.
- `GAP[HIGHER_HALF_EXEC] status=partial`: the kernel now jumps into its
  persistent higher-half alias for the live mainline, runs on a higher-half
  stack, rebuilds IDT gates for higher-half handlers, updates TSS `esp0`, and
  emits `khabi=` from guest assembly to prove the checkpoints, translations,
  page-table entries, and retained low-identity dependency were checked by the
  OS itself. The relocation-directory side now also emits `krelabi=` from guest
  assembly, proving the PMM-managed directory, high PDE, absent low PDE, text and
  stack translations, absent low translation, bounded high-only CR3 switch, high
  data write, blocked low return, and restored CR3. Remaining work before
  calling this done is the stronger relocation target: converting enough live
  kernel data references to high-safe addressing that the PMM-managed directory
  can stay active with the low identity mapping removed while the kernel keeps
  running.
- `GAP[PREEMPTION] status=partial`: timer IRQ preemption now switches Ring 3
  contexts through saved frames and `iret`, and the guest emits `preemptabi=`
  from the assembly scheduler path to prove the user IRQ frame, context save,
  target selection, process activation, IRQ-frame restore/rewrite, switch
  accounting, and preempt-probe spin capture all ran. The generated-WAD cloud
  smoke gate now requires this proof too. Remaining work is scheduler maturity:
  more than one policy, stronger starvation/fairness checks, and longer soak
  evidence under real gameplay load.
- `GAP[STORAGE_GENERALITY] status=partial`: FAT/WAD/save paths must keep becoming
  a general block-device and VFS subsystem for other programs. Cloud run
  `26293167954` on `main` proved the generic Ring 3 ABI path exercised every
  tracked VFS syscall with `vfsabi=000003FF/000003FF/00000200` and nonzero
  `vfsops` counters. The kernel now also emits `fatabi=` from the assembly FAT
  paths to prove allocation, free-chain, free-tail, zero-truncate, grow, shrink,
  delete, directory-update, and cluster-accounting operations ran in the guest.
  Remaining work is deeper filesystem generality: longer-lived allocation/free
  churn, more directory shapes, and persistence/save-load proof under real
  gameplay reboots.
- `GAP[INPUT_GENERALITY] status=partial`: keyboard and mouse feed one generic
  event queue, and the non-Doom `ABIPROBE.ELF` path now exercises the generic
  input ABI. Cloud run `26295614066` proved
  `input_abi=0000000F/0000000F/00000008/00000004/00000000` and
  `guest_input_abi_proof=true`: poll, aggregate status, keyboard status, and
  mouse status all ran outside Doom. Remaining work is a second interactive
  non-Doom input client and deeper stress of overflow/device lifecycle behavior.
- `GAP[GRAPHICS_GENERALITY] status=partial`: framebuffer presentation is now
  exercised through the generic user framebuffer ABI by `ABIPROBE.ELF`, not
  only by Doom. Cloud run `26294806487` proved
  `framebuffer_abi=0000000F/0000000F/00000001/00000000/00000004` and
  `guest_framebuffer_abi_proof=true`. Remaining work is richer device ownership
  and proof that another interactive graphical program can use the same path.
- `GAP[AUDIO_GENERALITY] status=partial`: SB16/DMA/PCM is now exercised through
  the generic user audio ABI by `ABIPROBE.ELF`, not only by Doom. Cloud run
  `26294418446` proved `audio=SB16`,
  `audio_abi=000001FF/000001FF/00000100/00000010`,
  `pcm_lifecycle=00000004:00000000:00000001:00000002:00000003:00000004:00000040`,
  and `guest_sb16_audio_abi_proof=true`. Remaining work is audible-output proof,
  deeper DMA/refill stress, and fuller Doom SFX/MUS behavior.
- `GAP[HOST_SCRIPT_RETIREMENT] status=in-progress`: legacy host scripts have
  been removed from the repo; remaining proof must stay shell/C/guest-owned.
- `GAP[PHYSICAL_HARDWARE] status=open`: QEMU PC hardware is the supported target.
  ACPI, HPET probing, and LAPIC/IOAPIC routing are only claimed inside that
  supported cloud QEMU machine model. Arbitrary laptops, disks, USB, AHCI, HDA,
  and real install recovery are not claimed.

## Evidence Standard

Do not claim a subsystem is done because a host tool inferred it. Claim it when
the OS emits status from the guest, a cloud boot exercises it, and the relevant
assembly/C path is visible in the repo.

WADs, generated disks, screenshots, raw audio, framebuffer dumps, and VM logs
must stay out of git and off the Mac.
