## Remote Doom Playtest Runbook

The safe path is `docs/play.txt`. Host checks stay local-only:

```sh
make ALLOW_LOCAL_VM=0 DOOM_WAD= build-only
python3 -m unittest discover -s tests/host -p 'test_*.py'
make playability-host-check
```

Cloud proof dispatches:

```sh
gh workflow run os-smoke.yml --ref "$branch" -f expected_ref="$branch"
gh workflow run real-wad-smoke.yml --ref "$branch" -f expected_ref="$branch"
gh workflow run real-wad-soak.yml --ref "$branch" -f expected_ref="$branch"
python3 tools/run_cloud_playability.py --ref "$branch" --lane gameplay --wait --download-artifacts build/cloud-run-gameplay
python3 tools/run_cloud_playability.py --ref "$branch" --lane audio --wait --download-artifacts build/cloud-run-audio
python3 tools/run_cloud_playability.py --ref "$branch" --lane persistence --wait --download-artifacts build/cloud-run-persistence
python3 tools/run_cloud_playability.py --ref "$branch" --lane full --latest-run --download-artifacts build/cloud-latest-full --checker-ref run --write-audit-log build/cloud-latest-full/cloud-playability-audit.json
```

For repeated soak dispatch, use the Run workflow branch selector carefully: the
workflow dispatches from the default branch, while `-f expected_ref="$branch"`
guards the intended proof ref.

The helper's failure lanes are gameplay/input, SB16 continuity, audible audio
aggregate, and persistence/save-load. Use `--lane gameplay`, `--lane audio`, or
`--lane persistence` to rerun only the red lane; persistence isolation can set
`audible_audio_proof=false`. Soak runs use `--soak-attempts`. Use
`--latest-run` when the proof already exists and the task is to download,
triage, and check the newest workflow-dispatch artifact for a specific ref
without starting another GitHub Actions run. Use `--checker-ref run` with an
existing run so downloaded proof artifacts are checked by the run's own checker
code instead of whatever the local checkout happens to contain. The optional
audit JSON records the requested ref, effective lane, smoke/soak workflow,
artifact policy, run metadata, checker ref, download/check commands, failure
lanes, and rerun lanes; it is proof bookkeeping, not a stronger claim than the
status artifacts themselves.

Human proof bundle files are status-only:

## Fault And Save Diagnostics

Doom user faults record `doomrun=FAULT` plus `doomfault=<cr2>`,
`doomfaultip=<eip>`, `doomfaultv=<vector>`, `doomfaulterr=<error-code>`, and
the compact `fault=` frame. Normal runs require `doomexit`, `doomfault`,
`doomfaultip`, `doomfaultv`, and `doomfaulterr` to stay zero.

The FAT16 image has root entries for `DEFAULT.CFG` and `DOOMSAV0.DSG` through
`DOOMSAV5.DSG`. Reboot comparison now requires the fresh baseline, the
after-write snapshot, and status evidence that Doom closed the save file before
the mutated image is inspected.
