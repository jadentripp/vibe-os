# Play vibe-os Safely

vibe-os is playable through a disposable cloud machine. Keep QEMU, WAD files,
disk images, pixels, raw audio, and VM logs away from the Mac.

## Fast Path

From the local checkout:

```sh
./tools/play_now_codespaces.sh --repo jadentripp/vibe-os --ref main
```

The launcher creates or reuses a GitHub Codespace, starts
`tools/play_now_remote.sh` inside that Linux host, makes the noVNC port private,
and prints the browser URL.

The Mac only talks to GitHub and opens a browser. It does not run QEMU and does
not receive the WAD or generated disk image.

## Browser-Only Codespaces Path

If local GitHub CLI auth does not have Codespaces scope:

```sh
./tools/play_now_codespaces.sh --web-url --repo jadentripp/vibe-os --ref main
```

Open the printed Codespaces creation URL, pick a 4-core or larger machine when
available, then run this inside the Codespace terminal:

```sh
./tools/play_now_remote.sh --preflight --require-novnc
./tools/play_now_remote.sh --require-novnc
```

Then open the forwarded port path:

```text
/vnc.html?autoconnect=1
```

## Disposable Linux Shell

For a cloud VM, Codespace terminal, or other throwaway Ubuntu shell:

```sh
curl -fsSL https://raw.githubusercontent.com/jadentripp/vibe-os/main/tools/play_now_cloud_shell.sh | bash
```

That script refuses macOS, installs the OS toolchain and noVNC packages, clones
the repo, and starts the same remote play launcher.

## Controls

```text
Arrows: move and turn
Ctrl: fire
Space: use
Escape: menu
```

Mouse support is part of the OS input stack, but keyboard is the most reliable
manual control path today.

## Safety Rules

- Do not run `make run`, `make run-headless`, `make smoke`, or QEMU locally on
  the Mac.
- Do not copy WADs, generated disk images, framebuffer dumps, screenshots, raw
  audio, VM logs, or `status.bin` files out of the disposable host.
- Keep `DOOM1.WAD` outside git. The remote launcher fetches and validates the
  public shareware WAD into `/tmp`.
- Delete the Codespace or cloud VM when done.

Cleanup commands printed by the launcher are the preferred way to stop or delete
the session.

## Local Build Checks

These commands are safe because they do not boot a VM:

```sh
make ALLOW_LOCAL_VM=0 DOOM_WAD= build-only
make ALLOW_LOCAL_VM=0 DOOM_WAD= test
make ALLOW_LOCAL_VM=0 DOOM_WAD= playability-host-check
```

They build the boot sector, Stage 2 loader, kernel, user probes, freestanding
Doom ELF, generated disk image, and minimal C status validator.

## Cloud Proof

Use GitHub Actions or Codespaces for any QEMU run:

```sh
gh workflow run os-smoke.yml --ref main -f expected_ref=main
gh workflow run real-wad-smoke.yml --ref main -f expected_ref=main
```

The formal proof direction is changing: guest status fields and small C/shell
checks replace the old host scripting layer. Optional proof lanes that do not
yet have a shell/C replacement should stay red rather than pretending to be
green.
