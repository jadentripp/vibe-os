# Test Strategy

The project is moving away from a large host scripting suite. Tests should prove
OS behavior through assembly/C paths, guest status fields, small C utilities,
and cloud boots.

## Host-Only Checks

Safe on the Mac:

```sh
make ALLOW_LOCAL_VM=0 DOOM_WAD= build-only
make ALLOW_LOCAL_VM=0 DOOM_WAD= test
make ALLOW_LOCAL_VM=0 DOOM_WAD= playability-host-check
```

These build the boot path, kernel, user probes, Doom ELF, image builder, and
minimal status validator. They do not run QEMU.

`tools/vibe_status_check.c` is the current status validator used by
`vm-status-proof-check`.

## Cloud Checks

QEMU checks run only on disposable cloud machines:

```sh
gh workflow run os-smoke.yml --ref main -f expected_ref=main
gh workflow run real-wad-smoke.yml --ref main -f expected_ref=main
```

Manual play runs through Codespaces/noVNC:

```sh
./tools/play_now_codespaces.sh --repo jadentripp/vibe-os --ref main
```

## Replacement Direction

- Prefer guest status fields over host-side inference.
- Prefer assembly at CPU, interrupt, syscall, paging, boot, and driver
  boundaries.
- Keep host C tools tiny: linker, image builder, status validator.
- Keep shell workflows honest: if a proof lane no longer has a shell/C
  replacement, it should fail with a clear message instead of passing.
- Do not add a new host scripting stack.
